# Native registered-memory destruction and address reuse

This separate runtime adds a native `__vpiArray` destructor that erases memory and scope observer registrations before later observation. Scope-object IDs use a monotonic counter with overflow refusal instead of registry size. The destructor does not erase the native scope vector during teardown iteration: a remaining stale intern entry is rejected by ownership validation before dereferencing it.

The explicit diagnostic API allocates a test-owned static memory, creates its word cache, deletes its storage/cache, invokes the native destructor, and leaves its scope entry deliberately stale. Memory metadata, dense arrays, compact arrays, scope metadata and scope references all refuse without output (20 refusals across four cycles). Removing the stale scope entry restores all five baseline inventories byte-for-byte. Placement construction reuses the same allocated object buffer in all four cycles, with fresh scope-object IDs 2, 3, 4 and 5. Every new memory has independently checked VPI values and complete dense/compact payload and cache ownership. Baseline, disabled and enabled HDL continuation matches.

The allocated object buffer stays reserved for deterministic placement reconstruction; this does not claim allocator-dependent reuse after freeing that buffer. Names follow the runtime permanent-name allocation convention. Test-owned memories have no compiled HDL references, read ports or callbacks. Full scope graph teardown, external dangling word handles, dynamic-array families and operational deletion remain unqualified. The queued continuous board runtime is unchanged.

Same-build regressions retain ordinary memory growth, parameter growth, unsupported-array families and native memory metadata/layout. Five replay/rejection tests check all reports, lost refusal evidence, ID reuse, omitted object registration and changed restored state. The source patch and builder are pinned below; native receipts bind all runtime outputs.
