# Native recovery after unsupported parameter refusal

Nine native runs compare original, disabled and enabled behavior for binary, real and string families. In each of two rounds, an unsupported subclass is allocated after the original inventory. Parameter observation refuses it and further supported allocation is refused. The fixture verifies its base VPI value, deletes it through the real native virtual destructor (freeing the allocation), and confirms that parameter, scope metadata and scope references refuse the stale scope entry without output. Removing that entry restores all original inventory bytes.

An exact supported parameter of the same family is then allocated successfully, fully observed with a fresh ID, and deleted. The stale entry again refuses and detachment restores all original inventories. The enabled controls cover six unsupported and six supported destructions, six unsupported inventory refusals, 36 stale-entry zero-output refusals and 12 exact recoveries/restorations. Supported 80-bit X-bearing binary values, real storage and embedded-null strings are checked independently of base VPI reads. Original HDL continuation matches in all nine processes.

Four replay/rejection tests cover the report, exact runtime identity, missing stale-entry refusal, a lost embedded null and altered restored original state. The runtime is the separate parameter-lifecycle candidate. This does not guarantee that the allocator reuses a freed address and does not qualify use of dangling external handles, deletion of compiled references, full scope teardown or board integration of recovery after unsupported-class refusal.
