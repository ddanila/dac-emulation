# Native inventory shutdown guard

The matched baseline sweep finds 15 AddressSanitizer failures after native cleanup, including heap-use-after-free in net and thread inventories. Of 55 inventoried APIs, 27 safely refuse and 13 still accept after cleanup. Both baseline and guarded runs use the same hierarchical fixture, three explicitly admitted signal handles and separate processes for each API. All diagnostics and source identities are retained.

The new candidate sets a shared observation-active flag false as the first operation of final_cleanup. Each of the 55 exported native inventory definitions checks that flag before touching output or registries. All 55 now refuse with -1 and zero output after cleanup; all processes exit cleanly with empty stderr. Pre-cleanup admission return codes and baseline HDL continuation match. Reapplying the exact source transformation to retained original sources reproduces every changed source file and the enumerated guard sites. Five replay/rejection tests pass.

The 52 one-stream APIs are enumerated from definitions. Three explicit adapters cover dense code operands, sync-family inventory with null expected identities, and the intentionally unsupported legacy sync API. This does not prove all observer families are populated, validate every payload, clear all runtime registries, support runtime reuse or concurrent observation, or make arbitrary getters/mutators and dangling handles safe. Leak and custom-pool checks remain disabled, and fixed VPI loader tables remain excluded from global instrumentation. Integrated board qualification of this new revision is separate.
