# Selected board memory lifecycle controls

The separate lifecycle runtime and bridge perform two diagnostic cycles at 5 and 6 microseconds. Each allocates a test-owned static memory and captures complete state, destroys it, requires direct memory and complete-snapshot refusal with unchanged logger cache pointers/sequences, removes the stale scope entry, and requires byte-exact complete restoration. The object buffer is reserved for placement reconstruction. The same native handle/concrete addresses receive fresh IDs 1933 and 1934.

Complete review validates eight snapshots across all existing observers, including 32 scopes, 18 bridge signals, 317 ports, 875 port bits, 651 complete signals, 56 parameters and the three compiled memories with 23 read ports. The created-state reviewer validates the additional memory's ownership, name, native layout, complete X-bearing payload and lack of caches/read ports. It removes only that validated addition from a copy, restores array numbering, and requires every other complete-state field to equal the before-state. The restored snapshot is compared without removing anything.

All 27,578 samples across 31 signals over 20 microseconds equal the retained original waveform exactly. Initialized models and every firmware record match. Four matching bus edges follow the second restoration, from 7,501,280 to 19,501,280 ps. Six focused state/source-preservation tests and four full replay/rejection tests pass, in addition to the two bridge/producer source checks.

The bridge's boundary ordinal pauses while waiting between selected cycles; the second recorded index is not a count of every underlying simulator hook. Timing and ordering are checked independently. This is selected-boundary qualification, not continuous observation. Test memories have no compiled HDL references, read ports or callbacks. Complete graph teardown, deletion of live compiled memories and dangling external handles remain separate. Existing queued operational campaigns and full-repeat deferral are unchanged.
